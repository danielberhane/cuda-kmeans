# CUDA K-Means Clustering

K-means clustering on the GPU, written in CUDA C. Three kernels per iteration, a
two-stage reduction, and one shared-memory buffer carved into six regions. Works on
data with any number of dimensions.

package (Wei-keng Liao / Serban Giuroiu). `MyCUDA` is this repository.

| 2   | ~0.06 s   | ~0.10 s | ~0.10 s | **~0.16 s** | ~0.19 s   |

At K=100 this is about **5× faster than sequential**. The CPU versions grow roughly
linearly with K; both GPU versions stay nearly flat.

### Where it loses

At K=2 the GPU is 4–10× slower than the CPU, and its time is the same (~0.17 s) for
10,000 points as for 100,000. That is fixed cost: context creation, host↔device
transfers, and a blocking copy every iteration. With so little arithmetic per iteration,
none of it is hidden.

### Per-kernel bandwidth

n=100,000, k=100, d=1, block size 128:

| Kernel | Read | Written | Time | Effective BW |
|--------|------|---------|------|--------------|
| 1. `find_nearest_cluster`    | 801,400 B | 1,024,800 B | 0.24 ms | 6 GB/s* |
| 2. `reduce_coord_clusters`   | 627,000 B | 800 B       | 0.18 ms | 3.48 GB/s |
| 3. `reduce_cluster_changed`  | 3,124 B   | 6,248 B     | 0.12 ms | 0.078 GB/s |

Kernel 3 takes 22% of the kernel time to move 0.5% of the bytes. It runs as a single
thread block, so one SM works while the rest of the device waits. Spreading that
reduction across blocks is the obvious next improvement.

\* Does not follow from its own inputs (which give 7.61 GB/s). See
[`presentation/BENCHMARKS.md`](presentation/BENCHMARKS.md).

## How it works

Each iteration assigns every point to its nearest centroid, moves each centroid to the
mean of its points, and stops when fewer than `threshold` points change cluster.

1. **`find_nearest_cluster`**: one thread per point. Finds the nearest centroid and
   accumulates per-block coordinate sums in shared memory.
2. **`reduce_cluster_changed`**: counts how many points moved.
3. **`reduce_coord_clusters`**: sums the per-block partials into global totals.

The host transposes the data from `[N][D]` to `[D][N]` once before upload, so each warp
reads a coordinate as one contiguous, coalesced access. Centroid division and the
convergence test run on the host, which means δ is copied back between kernels 2 and 3
every iteration. That copy is what the K=2 numbers are measuring.

## Modern hardware

This was written in 2015, when the 32 threads of a warp were guaranteed to run in
lockstep. Four reductions relied on that and unrolled their last warp with no
synchronisation. Volta (2017) removed the guarantee. On an A100 the reductions lose
updates, the changed-point count comes out low, and the loop stops after 6 iterations
instead of 31.

Three fixes are in this repository:

- The four reductions synchronise at every step.
- `reduce_cluster_changed` folds strided slices instead of one thread per block. This
  removed a hard limit at N=131,072, where the launch asked for more than 1,024 threads
  and failed.
- `s_membership` is written for every thread. It was only set for points that changed
  cluster, so from iteration 2 the centroid sums read uninitialised shared memory.

The scaling sweep now runs to 5,000,000 points on an A100 where it used to crash at
250,000. Even so, **the code is not yet verified correct on Volta or later**: an A100
run still disagrees with the CPU baseline on iteration count, and the benchmark
[refuses to report timings](bench/README.md) until they match. The 2015 figures above
were measured on the hardware this was written for.

## Build and run

Requires the CUDA Toolkit and a CUDA-capable GPU.

```bash
make                          # main executable
make GENCODE="-arch=sm_80"    # set the architecture for anything you benchmark
make cuda_kmeans_bench        # instrumented build, per-kernel timings
make bench-tools              # CPU baseline + data generator (no CUDA needed)

./cuda_kmeans <num_clusters> <num_dimensions> <num_points> <threshold> <input_file> [--csv]
./cuda_kmeans 4 3 99968 0.001 data/points_3d.txt
```

Writes `<input>.cluster_centres` and `<input>.membership` next to the input. `--csv`
prints one machine-readable row instead.

The bundled datasets have no cluster structure. They measure throughput, not clustering
quality. To run the full benchmark, see [`bench/README.md`](bench/README.md).
